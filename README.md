# 依恋地图 · Attachment Map

基于成人依恋理论的双维度测试站。**零依赖、零构建步骤、零后端**——把目录拖到任何静态托管上就能跑。

**线上地址**：<https://luckyboom1.github.io/attachment-map/>（GitHub Pages 项目站点，公开仓库）

---

## 快速开始

```bash
# 1. 启动本地服务（零依赖，只用 Node 内置模块）
npm run dev          # → http://127.0.0.1:5173

# 2. 跑核心逻辑自检 + 二维码交叉验证
npm test             # 132 项核心逻辑 + 64 项二维码

# 3. 全部静态检查（结构 / DOM 契约 / 核心逻辑 / 二维码）
npm run check

# 4. 需要验证后端契约时（可选）
npm run dev:api      # 启用 /api/v1/* 桩实现
```

> 为什么必须用服务器打开？项目用了原生 ES Modules，`file://` 协议下浏览器会因 CORS 拒绝加载模块。任何一个静态服务器都可以，不限于本项目自带的。

## 架构要点

### 1. 三层分离，越界即错

| 层 | 位置 | 规则 |
|---|---|---|
| **确定性内核** | `core/` | 可复现。禁止随机数、网络请求、时间戳。可脱离浏览器单测 |
| **数据出入口** | `api/` | 页面只允许 `import { api } from '../api/index.js'`，不得直接碰 `local.js` / `remote.js` / `store.js` |
| **页面** | `pages/` | 只做渲染与交互，不含业务计算 |

### 2. AI 的位置：只写文案，不判类型

```
题干 → 计分 → 维度分 → 常模标准分 → 象限分类     ← 确定性，不可用 AI 替代
                                          ↓
                            报告文案 / 相处建议   ← 目前是模板，将来可接 LLM 润色
```

**绝对不允许让大模型读原始答案判断类型。** 否则同一用户今天测出「焦虑型」、下周测出「安全型」，产品可信度一次性归零。`core/report.js` 输出的章节是「事实骨架」，将来接 LLM 时模型只能改写措辞，不得增删事实条目，不得改变类型判定。

### 3. 双人合盘的零后端方案

不建房间表、不建数据库。把两人的答案编码进 URL：

```
duo.html?a=<base64url(甲答案)>&b=<base64url(乙答案)>
```

- 每个答案 1–7 → 0–6，占 3 bit；36 题共 108 bit → 14 byte → **base64url 19 字符**
- 收益：零后端、零数据库、零用户数据存储、零泄露风险、零服务器成本
- **关键**：它天然满足「对方没测之前不显示结果」——因为对方的数据物理上还不存在，不需要任何权限校验，架构本身解决了这个约束

### 4. 为什么自己写二维码，而不是引库或调接口

因为**二维码里装的就是用户的答案**。邀请链接是 `duo.html?a=<19字符>`，那 19 个字符是 36 道题的编码。一旦把这个链接丢给第三方二维码服务，就等于把作答原文发了出去——前面五个「零」全部作废。

外链库也不行：会破坏「零依赖、零构建」这条底线。所以 `core/qr.js` 是一个自带的实现：

| 项 | 取值 | 理由 |
|---|---|---|
| 模式 | Byte（UTF-8） | 链接里必然有小写字母，Num / Alnum 模式都不适用 |
| 纠错等级 | M | 约 15% 冗余；屏幕→摄像头对污损不敏感，M 够用 |
| 版本 | 1–7 | V7-M 可装 122 字节。实测合盘链接 ≤ 90 字节，留了 35% 余量 |
| 超出容量 | 返回 `null` | **宁可不画，也不画一个扫不出来的码**；UI 降级为「复制链接」 |
| 掩码 | 8 种全试，按规范罚分取最低 | |

二维码样式上被当作一张「纸」：无论深浅主题，始终黑码白底。深色主题下若反转成白码黑底，多数相机直接扫不出来——所以 `--qr-*` 这组令牌**刻意不在暗色主题里覆盖**，这是有意的例外。

**正确性怎么保证的**（自研编码器最危险的失败模式是「看起来像二维码、扫不出来」，界面上完全看不出来）：

```
npm run check:qr
```

三层验证，从算得对到扫得出来：

| 层 | 对手 | 做了什么 |
|---|---|---|
| 编码器 | python-qrcode | 8 个用例（覆盖 V1–V7，含中文与真实合盘链接）× 8 种掩码 = **64 次逐模块比对**，全部一致 |
| 罚分实现 | python-qrcode 的 `lost_point` | 64 个矩阵上的罚分**逐值相同**，择码结果 8/8 一致 |
| 解码器 | segno | 把另一个独立实现生成的矩阵喂进我们的解码器，必须读回原文、且每块 Reed-Solomon 校验子为零 |

外加边界与结构不变量：分块表自洽、超长返回 `null`、定位/时序/校正图形、版本信息 `0x07C94`、格式信息 8 种掩码可读回、真实链接容量实测。

**但「矩阵算得对」还不等于「扫得出来」**——自研二维码最危险的失败模式恰恰是结构看着对、相机就是扫不出来。所以还有一层像素级验证：

```bash
npm run check:qr:scan      # 需要 python + opencv-python-headless
```

它把生成的 SVG 光栅化成位图，交给 **OpenCV 的真实二维码解码器**读回来，覆盖 5 个用例（V1/V3/V5/V6/V7）：

| 场景 | 结果 |
|---|---|
| 基线渲染（8 像素/模块） | 5/5 读回原文 |
| 3 像素/模块（小屏幕上的一张小码） | 5/5 |
| 倾斜 12°（手机扫屏幕很少正对） | 5/5 |
| 模糊 + 噪点（手持抖动与摄像头噪声） | 5/5 |
| 负向对照：纯噪声图 | 5/5 读不出结果 |
| 负向对照：涂白约 20% 模块 | 5/5 读不出原文 |

负向对照是必要的：只证明「能读出」不够，还要证明「坏到一定程度就读不出」，否则无法排除判据过宽导致的假阳性。

基准数据（`tools/qr-reference.json`）是**已提交的固定文件**，所以跑 `npm test` / `npm run check` 不需要装任何东西。要重新生成才需要 Python：

```bash
pip install qrcode segno
npm run qr:reference
```

> 记录在案的一处差异：segno 的 `write_padding_bits` 在字节已对齐时仍会多补 8 个零位（`buff.extend([0] * (8 - (length % 8)))` 未判断 `length % 8`），与它自己引用的规范文字不符。两种产物都是合法可扫的二维码；我们按规范实现，不向它靠拢。这也是为什么编码基准用 python-qrcode、解码基准用 segno——各取所长。

### 5. 换后端 = 改一行配置

```html
<script>window.__AM_CONFIG__ = { mode: 'remote', baseUrl: 'https://api.example.com' };</script>
```

`api/index.js` 会根据 `mode` 装配 `remote.js`。页面代码一行都不用改。启动时会用 `assertAdapter()` 校验适配器是否实现了契约的全部方法——缺方法会立刻报错，而不是等某个页面崩掉。

## 关键交互决策

| 页面 | 决策 | 依据 |
|---|---|---|
| 入口页 | 首屏四问一行一个答案；**不放任何付费信息** | 用户还没体验到价值，此刻谈钱只会赶走他 |
| 答题页 | 进度显示「还剩 N 题」而非「完成 X%」 | 用户想知道的是剩余成本 |
| 答题页 | 点选项即进下一题，无「下一题」按钮 | 少一次点击 = 少一次流失 |
| 答题页 | 选中态 100ms 内出现，180ms 后推进 | 太快看不清反馈，太慢像卡住 |
| 答题页 | 不做「你还没答完」拦截 | 允许随时离开，localStorage 自动存 |
| 结果页 | 3 秒法则：类型名 → 一句话 → 可截图卡片 | 转化生死线 |
| 结果页 | 付费按钮说清买到什么，不用「立即解锁」 | 用户需要知道买的是什么 |
| 结果页 | 截图引导显眼但不遮挡结果 | 遮挡等于掐断裂变 |
| 合盘页 | 对方未测时**不显示任何结果** | 用架构解决约束，而不是用提示语 |
| 结果页 / 合盘页 | 邀请二维码直接显示，不藏在按钮后面 | 对方在场时扫码是主路径；多一次点击就多一次流失 |
| 二维码 | 固定黑码白底，不跟随深色主题反转 | 白码黑底多数相机扫不出来，可扫性优先于主题统一 |
| 报告页 | 解锁后 0.1 秒内可见 | 任何延迟都会让用户认为被骗 |

## 常模：两套参照，必须分开

状态（2026-09-11）：`source: 'published'`，已引用公开发表的中国大学生样本，不再是暂定值。

但**类型判定与百分位用的是两个不同的参照**，这是本模块最容易搞错的地方：

| 用途 | 参数 | 取值 | 依据 |
|---|---|---|---|
| **类型判定**（高/低、四象限、强度分档） | `NORMS.cut` | 4.0 | 量表中点。中文文献对 ECR/ECR-R 四型的定界惯例是「取两维度均分，以 4 分为界」 |
| **百分位**（相对谁在什么位置） | `NORMS.anxiety/avoidance` 的 mean/sd | 焦虑 3.77 ± 0.85；回避 3.40 ± 0.82 | 李梦霞等（2010），中国公共卫生 26(7): 864-866；浙江省 6 所高校有恋爱经历大学生，N=547 |

**为什么不能合并成一个数**：若用 z > 0 判型，就等于拿引用样本的均值（3.40）当本站题目的切分线，会产出「百分位 77，却被判为低回避」这种自相矛盾的输出。根因是本站题本是该构念的改写版，没有自己的实测分布，而借用来的样本均值低于量表中点。所以：**切分点非到有本站样本不得改成样本均值**（`selftest` 有回归测试固定这一点）。

结果页会把两条线同时画在维度条上并分别标注，方法说明页列出口径对照表。

**参照样本的波动范围**（`NORMS.crossCheck`，方法说明页会渲染成表）：

| 来源 | N | 依恋焦虑 | 依恋回避 |
|---|---|---|---|
| 田瑞琪（2004）· 上海师大硕士论文 | — | 3.54 ± 0.84 | 3.14 ± 0.82 |
| 李梦霞等（2010）· 中国公共卫生 ← 本站参照 | 547 | 3.77 ± 0.85 | 3.40 ± 0.82 |
| Frontiers in Psychology（2023）· 昆明医科大学 | 477 | 3.60 ± 0.81 | 3.47 ± 0.80 |
| 农村留守经历大学生（2010）· 中国公共卫生 | 1062 | 3.82 ± 0.82 | 4.16 ± 0.53 |

普通大学生样本的区间是「焦虑 3.54–3.77、回避 3.14–3.47」，跨研究差异约 ±0.2；亚群体（如童年留守经历）会明显偏移。列出多个样本而不是一个点估计，就是为了让这个不确定性可见。

**升级路径**（按优先级）：

1. ~~引用公开发表的中国样本~~ → **已完成**
2. 用本站真实样本的中位数重算 → 服务端实现 `GET /api/v1/stats/norms`，`source` 改为 `site-sample`。这一步会把 `cut` 从「量表中点」换成「本站样本中位数」，**届时两个口径才统一到同一参照系**
3. 两者都拿不到 → 不输出四类型标签，只展示维度分与百分位

**明令禁止**

1. 直接套用美国/西方样本的 mean / sd。中文样本的依恋焦虑均值系统性偏高，用错常模会把大批用户误判为焦虑型。这是 P0 级事故。
2. 在没有本站数据的情况下把 `cut` 改成引用样本的均值。见上文。
3. 只改 `NORMS.anxiety/avoidance` 却忘了同步 `crossCheck` 里的主参照——`selftest` 有一条专门防这个，否则页面会自相矛盾。

## 关怀契约（不可妥协）

代码里以测试形式固化，`npm test` 会检查。**其中 3、7 两条不只查「有没有」，还查「在不在免费区、在不在付费墙之前」**——文案里写了却要付费才看得到，等于没给。

| # | 规矩 | 测试怎么查 |
|---|---|---|
| 1 | 不宣称诊断效力 —— 任何页面不出现「诊断」「治疗」「心理疾病」 | 全文扫描 |
| 2 | 不使用贬损词汇 —— 不出现「缺陷」「不正常」「有病」「冷漠」，也不用「你踩的坑」这类归罪式说法 | 禁用词表（含报告章节标题） |
| 3 | 必须给出可改变的出口 | 扫描报告全文；**并断言出口的渲染位置早于付费墙渲染位置** |
| 4 | 不做未成年人的情感类型判定 | 面向成年人 |
| 5 | 不诱导重复付费 —— 复测永远免费 | 复测不设门槛 |
| 6 | 不把结果用于评判他人 —— 不提供「给伴侣贴标签」的功能 | — |
| 7 | 必须给出求助入口，且放在变现动作之前 | 断言热线号码存在，**且其位置早于付费墙** |

除红线外，还有两条针对「被关心感」的测试：

- **答题过程必须有陪伴语**：36 题里 28 题在让用户确认自己的不安，连续确认本身就是情绪负荷。断言 `#cushion` 存在、至少 3 段、且**不含催促性措辞**（「加油」「马上就好」这类会把陪伴变成压力）。
- **时长承诺不得低于实际体感**：断言入口页不再出现单值「约 3 分钟」，且给出区间与「答慢一点没关系」。

背景与完整的界面评审见 `../依恋地图_界面关心度评审.md`。

## 部署

纯静态，无构建步骤。

| 平台 | 做法 |
|---|---|
| GitHub Pages（项目站点） | 仓库推送后在 Settings → Pages 选分支即可，地址为 `<用户名>.github.io/<仓库名>/` |
| Cloudflare Pages | 直接连仓库，构建命令留空，输出目录填 `/` |
| Vercel | 框架选 Other，构建命令留空 |
| 任意虚拟主机 | 用 FTP 把整个目录传上去 |

### GitHub Pages 三件必须知道的事

1. **一个账号只有 1 个用户站点**（`<用户名>.github.io`），但**项目站点数量不限**（`<用户名>.github.io/<仓库名>`）。所以不必抢用户站点，建一个仓库当项目站点即可。
2. **商用限制**：GitHub Pages 的服务条款写明「不用于经营在线业务、电商，或以促成交易为主要目的的网站」。当前免费期没问题；**一旦接入 ¥9.9 / ¥29.9 的付费解锁，就必须迁走**，否则有被停服的风险。
3. **子路径**：部署到 `…/<仓库名>/` 时，站内链接与二维码都已按相对路径处理（`new URL('./', location.href)`），海报二维码测试覆盖了这一场景。仓库根目录加一个空文件 `.nojekyll` 可跳过 Jekyll 构建，避免发布被无谓处理。

其他用量限制（官方数字）：仓库建议 ≤ 1 GB、已发布站点 ≤ 1 GB、部署超过 10 分钟超时、**每月软带宽 100 GB**、**每小时软限制 10 次构建**（用自定义 GitHub Actions 工作流构建时不受此限）。

## 免费运行说明

当前 `api/index.js` 中 `CONFIG.freeMode = true`：

- 全站不收费，`createOrder` 返回 `amountCents: 0` 且 `status: 'paid'`
- UI 上如实标注「免费体验期」，**不伪装成已支付**
- 目的是让整条漏斗（结果页 → 付费墙 → 报告页）可以被真实走通并埋点，而不是做一个点不动的假按钮

接入正式支付时，把 `freeMode` 改为 `false`，并在 `api/local.js` 的 `createOrder` 中走真实支付分支（结构已写好，只是当前不可达）。
